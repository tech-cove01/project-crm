# CRM-021c：检索词面覆盖修复与待验范围

2026-11-01。依据 [CRM-021](../CRM-021-spec.md)，修复 [020d](CRM-020d-data-boundaries.md) 的 K03/K04 漏检与 [018a](CRM-018a-no-answer-retrieval.md) 已知词面损失。本页记录源码与直接离线检查；后续[真实 17 题回归](CRM-021c-retrieval-regression.md)已完成，指定漏检恢复、五个无答案样本为空，D02/F06 各缺一页的覆盖限制仍保留。原题、标签、失败和分母不改，不称盲测或总体召回能力认证。

## 原因

已保存的 K03/K04 均为原句零候选、关键词分路两张候选，随后 A/B 页面读取成功，却没有进入来源文档读取或证据回执写入。差异发生在支持门禁，不是没有发现候选或来源授权失败。

- K03 的有效词为销售、协同、客户、自动、过来；A 缺少“客户、过来”。分词还丢失了单字动词“搬”，没有保留数据迁移意图。
- K04 的有效词中，B 缺少“直接、邮件、允许”。其人工决定前置条件和不授权外部消息的上位政策不能通过逐字 AND。
- 旧 F01 要求出现“框架”，原文使用“架构”，因此丢失原相关页。

## 有界通用规则

实际调用仍使用现有 `searchCompanyWiki` 和 `supportsWikiQuery`；只改查询 helper 及直接测试，没有改 `weknora.ts`。原句字面转义、每 KB 仅零候选后一次回退、六个候选搜索词、32 个支持词和 2000 字符上限、15 秒截止、来源授权/发布状态/文档版本/正文哈希及不可变证据回执链保持。

1. 归一化框架/架构、电子邮件/邮件。只有紧邻数据、文件、记录或资料的方向搬移表达才按迁移匹配，不把家具、人员等搬运归入数据迁移。
2. “替/帮/为客户或用户把/将”只在明确受益对象结构中处理，不全局删除客户或用户。许可算子只在明确的政策许可问句处理；“直接”缺失时，还必须有实际人工决定前置条件，不能任意忽略操作限制。
3. 邮件或短信不无条件等同消息。只有明确外发许可问句、实际页面存在无条件禁止外部消息的上位政策，才可覆盖缺失的子渠道词；正面支持消息、条件例外、双重否定或矛盾的正面许可不能建立该覆盖。
4. 其他实际属性仍逐项 AND。数字、日期和数量单位保留；紧邻“哪/哪些”的“三类/三种”等明确枚举问句可作为请求算子，不能据此断言来源已证明该计数。“最多支持三类文件”等实际属性不删除。只有数量而没有主题的查询不新增宽泛回退。

仅实际标题和返回范围内正文参与支持判断，slug 和搜索摘要不作支持。这仍是有限词法规则，不能证明语义蕴含、完整可回答性或最终回答正确；条件语言和近义词也没有开放域覆盖保证。
