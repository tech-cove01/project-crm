## 六个数据边界

| 场景 | 实际调用或注入 | 观察结果与范围 |
| --- | --- | --- |
| Mem0 不可用 | 真实适配器的 fetch 在进程内注入不可用异常 | 返回 `local_fallback` / `providerStatus=unavailable`，三条当前 SQL 事实完整保留；不是物理停止 Mem0 服务。 |
| 同 ID 哈希更新 / 旧投影 | 固定 user/run GET 读取真实旧 Mem0 回执；同一 PG 连接事务在搜索等待点更改本批一条记录，回放该旧投影 | 二次 SQL 读取返回新正文/哈希，未返回旧正文；事务 rollback 后原三条正文/哈希一致。不是新增正文编辑 API。 |
| 删除 / 旧投影 | 同样读取真实旧回执，在同连接事务中删除该记录后回放投影 | 删除 ID/旧正文不返回，其余两条保留；rollback 恢复三条原事实。 |
| Wiki 改版 | 自有 A 页真实乐观版本 PUT，旧引用回读及一次 `CSV` 重检 | 旧引用失效，新检索观察到版本 2；随后以另一版本 PUT 恢复原正文，当前版本为 3，没有伪造回版本 1。 |
| Wiki 来源撤回 | 固定组织/来源/KB/精确时间戳 CAS，实际撤回后恢复资格 | 撤回时旧引用不返回正文；恢复为 ready/active，但 revision 前进，旧引用仍失效；一次 `审批` 重检产生当前来源的新证据。 |
| KB binding 撤权 | 仅执行进程的可信 binding 副本移除新 KB，再调用真实适配器并恢复 | 旧引用被拒绝，新 KB 无返回证据；RAM 恢复后可回读。没有修改活动配置或重启服务，不称 Web 授权撤回实测。 |

六项均完成既定断言和恢复核对。记忆的三个搜索调用由进程内故障/旧回执回放截获，没有发送实际 Mem0 向量搜索；哈希更新和删除只存在于回滚事务。Wiki 的页面和来源变化是真实持久变更，正文/资格恢复后仍保留新的版本或 revision。引用失效仅指已核验的回读和重新检索时点，不保证已有回答自动撤销。
