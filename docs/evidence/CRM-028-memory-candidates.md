# CRM-028 从历史单聊到确认记忆

联系人页允许有权限的经理和管理员，从一个授权历史单聊中提取有原文依据的候选。提取只向 Gateway 提供近 90 天至多 20 条有界入站文本。原文须逐字匹配当前消息。候选表只向 service role 授权，保留原消息 ID、来源摘要和引文位置，供待审时授权回读。已处理候选的接口回执只返回状态等元数据。

确认事务会重查成员、支持会话及当前联系人，锁定候选和证据，同时写入人工决定、确认事实与原有 Mem0 同步事件。同一决定重放返回原结果。候选对 Pi 读取不可见，确认事实沿用现有 SQL 回读和撤回。联系人匿名化、合并和删除时清理候选。

## 真实提取与人工决定

真实 `dashscope/qwen3.8-flash` 从历史单聊 `4463a585-732d-4ce8-bd58-4497b5c4145c` 提出 4 条候选，4 条引文逐字可核。人工选择了其中的沟通偏好 `f61e792b-db1a-4ddd-8851-85b33b579b31`。其原文是“回访前先发一条标题含「蓝杉窗口」的中文消息，这是我的固定沟通偏好。” 同一消息里另有一条提及“周二 16:40”的独立候选未确认。确认前，所选联系人和同组织另一联系人的 SQL 召回均为空，事实、同步事件和 Workbench 根 Run 都为 0。

独立管理员用同一个候选 ID 并发提交两次确认，两次均返回 200 和事实 `eedf303f-dbf3-4d2d-9838-0c02c7e47819`。独立 SQL 回读确认新增 1 条事实和 1 条 Mem0 同步事件，事实的请求键为候选 ID，确认人为该管理员。已确认事实在所属联系人可读 1 条，同组织其他联系人和异租户均读到 0 条。本机 Mem0 禁用，事实与同步事件由 SQL 核验。
