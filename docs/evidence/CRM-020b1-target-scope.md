# CRM-020b1：工作台精确对象范围

日期：2026-11-01。对应 [CRM-020](../CRM-020-spec.md) 的授权负例。仅核验本批自有合成对象，不调用模型、Judge、客户渠道或真实 HTTP 工具接口。

## 首轮发现与修复

原工具桥会校验组织、角色及漏斗，但未将显式工具目标与工作台选中的对象逐值比较。选中一个商机后，同组织、同漏斗的另一个商机仍可能进入 `crm_move_lead_stage` 的真实 handler；提示词中的精确对象说明不能提供服务端保护。

本次首先使用真实 PostgreSQL、现有 MCP 工具桥和阶段变更 handler 复现：事务内的临时错误商机由初始阶段变至目标阶段，授权负例判 **fail**。随后外层事务回滚，主商机恢复原快照，两个临时商机均不存在。原失败报告保留。

第一轮修复在 MCP 工具桥进入对象查询或 handler 前增加精确目标门禁。有选中对象时，显式 `lead_id/contact_id/conversation_id`，以及 `target_kind/target_id` 的商机、客户、会话目标，必须匹配对应选中 ID；缺少该类选中对象时不自行扩大范围。同一 UUID 的大小写等价。普通非工作台调用与未选中对象的工作台仍沿用原组织、角色和漏斗校验。

调用上下文接入初始执行、续跑、只读专家、批准和撤销入口。范围使用解析后的关联对象，选择商机时可包含解析得到的关联客户。撤销入口在认领前解析对象；工具返回明确拒绝时，不能写成 `undone` 或记录成功业务变更。此项接线与并行的专家冲突复核门禁分别提交。

## 定向复查

| 代表检查 | 首轮 | 修复后 |
| --- | --- | --- |
| 同组织、同漏斗的错误商机不得变更 | fail：事务内发生变更 | pass：明确拒绝，阶段及快照不变 |
| 实际存在的另一合成组织商机不得变更 | pass | pass |
| `to_stage_id` 为数值的错误参数 | 既有工具 Schema 拒绝 | 既有工具 Schema 拒绝 |
| 选中主商机的正向 handler 控制 | 事务内阶段变更有效 | 事务内阶段变更有效 |
| 外层回滚、主商机快照恢复、临时商机不存在 | pass | pass |

每次实验仅用一个 PostgreSQL 连接；临时另一组织及其客户、漏斗、阶段、商机也在同一外层事务中建立。SQL 执行前核对本批客户的 `source_metadata.synthetic/batchId`、商机完整描述中的精确 marker、合成标签及关联身份，另核组织模型配置。没有持久化这些实验写入。

为将所有业务写入保持在该事务内，实验将 Supabase 查询传输适配为同一 pg 连接，并抑制辅助 audit、`emit_event` 和活动投影传输；实际阶段变更 handler 及其数据库更新执行，所有 HTTP 调用被禁用。故此证据是**真实数据库和 handler 的事务回滚实验**，不代表真实 HTTP、RLS、完整审计投递或后台恢复验收。两份结果均为 HTTP 尝试 0、异步数据库错误 0、`rollbackConfirmed=true`。

13 项新定向检查覆盖各显式目标、混合参数、多态目标、UUID 大小写、空范围、普通正文不误判，以及读/写工具在任何查询和 handler 前被拒绝；另有 6 项既有批准工具检查，共 19 项通过。限定文件 ESLint 通过。首次单元检查因沙箱临时缓存权限失败，0 项执行；修正执行权限后的单次技术重试取得上述结果，不计作业务复跑。核心实现已由另一 agent 独立审查。
