# CRM-022d 记忆三臂对照

2026-11-16，在隔离 PostgreSQL、真实本机 Mem0 和 DashScope `qwen3.8-flash` 上完成 1 题校准和 6 题正式配对，共 21 次模型请求。正式对照中，无跨会话事实、SQL 最新 10 条、SQL 加 Mem0 重排 10 条分别通过 **0/6、4/6、6/6**。SQL 让四题取得必要事实。Mem0 又补齐一条较旧沟通事实和候选窗口内第 50 条事实，改善两题，另四题持平。这个结果支持保留现有排序。当前切片收口，扩大对照和经济性判断留待更多样本及实际账单。

## 设计与固定条件

产品基线 `60f2ba577f9f113eadba6fa89d0c6d308dd04613`。校准独立使用 1 个合成客户、2 条事实。正式使用 5 个合成客户、78 条初始事实，分别含 3、18、51、3、3 条。修改保留原事实 ID 并更新 SQL 正文和哈希，删除用 SQL 墓碑排除一条事实。两项在隔离事务中布置，Mem0 保留旧投影供核查。题目、真值、正文及证据关联预先冻结，并与发给模型的字段说明分开。每题一次三臂，轮换各臂顺序。详见[冻结用例](../../scripts/eval/crm022-memory-cases.ts)及[评测规格](../CRM-022-spec.md)。

三臂共用同一只读系统提示、字段说明、事实投影结构及预算。无跨会话臂传空事实数组。SQL 臂在评测进程内禁用 Mem0 绑定，调用真实产品读取函数得到最新 10 条。Mem0 臂调用同一函数，沿用 `crm_get_contact` 的默认搜索文本 `Customer preferences and confirmed communication context`，由当前 SQL 的最近 50 条有效确认事实约束候选，匹配远端 ID 和哈希后排序，最终返回最多 10 条。模型只看到 SQL 当前正文。每臂使用单次真实模型请求，温度 0、关闭 thinking、输入上限 12,000 字节、输出上限 650 token、超时 30 秒。模型步骤是独立单轮样本，采集真实适配器投影和同一提供商的终答，评测范围为事实选择与答案正确性。见[模型和评分代码](../../scripts/eval/crm022-memory-score.ts)及[运行入口](../../scripts/eval/crm022-memory.ts)。

真实本机预检核对隔离组织、绑定、Mem0 协议、SQL 最新顺序及回滚，评分正反例 5/5。校准三臂均返回 HTTP 200，JSON 结构通过。无记忆臂正确留空，SQL 和 Mem0 臂均答对并引用事实。校准计量为输入 1,024、输出 116 token，独立于正式分母。

## 正式结果

三臂各完成 6/6，18 次模型响应均为 HTTP 200 并正常结束，18 次输出格式通过。任务通过要求所有字段的值和证据都正确。应留空的字段要求值和证据 ID 同时为 null。字段正确率的分母为 10 个字段，包含 8 个应取得的确认字段和 2 个应留空字段；8 个确认字段对应 7 个题目与来源事实的组合，M02 的两个字段来自同一条事实。

M04、M05、M06 分别检查窗口外、修订和删除三种不应使用的值，三个臂均未在终答中使用这些值。过期判定只覆盖这些实际观察，通用有效期或自动衰减不在当前实现范围。另在 18 条夹具上将 Mem0 的一次搜索在进程内注入传输故障，真实 SQL 返回顺序与 SQL 臂相同的 10 条，状态为 `local_fallback` / `unavailable`，耗时 12.69 ms。该故障探针独立于正式模型矩阵。

## 隔离、复现和边界

正式批次的 78 条投影均通过产品同步入口创建，使用本机 embedding 和 `infer:false`。六次实际 Mem0 搜索均成功。实验结束后，78 条投影按本批 user/run 和精确回执逐条删除并读回验证，五个客户及其 SQL 事实在事务回滚后查验为零。清理范围只含本切片自有事实与投影。正式评测的 552 次 Mem0 HTTP 请求由同步 312、搜索 6、清理 234 组成。故障注入的那一次没有离开进程。每臂延迟表只包含当题检索和模型请求，不把夹具同步或清理并入。正式批次从启动到报告落盘约 32.74 秒。

复现入口为 `node --import tsx scripts/eval/crm022-memory.ts --freeze`，可离线生成带源码与题集哈希的计划。`--check-local` 要求已配置的隔离库和本机 Mem0，会核验评分及回滚。实际校准和正式阶段通过 `--run calibration|formal <plan-path> <plan-sha256>` 执行，各需要隔离环境与明确的真实请求额度。每臂的 intent 和结果单独落盘。报告仅保存模型可见终答、事实投影、用量及核对结果，密钥保持在进程内。
