# CRM-022 能力效果与执行可靠性实测

2026-11-15，产品基线 `60f2ba577f9f113eadba6fa89d0c6d308dd04613`。本批使用合成客户、商机、确认事实、产品资料，组织隔离。冻结清单另记实际依赖、任务/数据/核验脚本 SHA-256、授权工具和配置。校准与保留结果分开，运行失败按原始类型保留。

## 对照设计

| 验证 | 样本计划 | 固定变量 |
| --- | --- | --- |
| 单 Agent / 三专家 | 另设校准任务。正式题按简单查询、跨来源、冲突、缺证均衡取样；先以每类3题规划，另在每类预先指定1题成对复跑一次。每对交替先运行哪一臂。 | 同一销售 Agent、模型、任务、商机和数据快照，inspect 模式，单 Agent 有事实/商机/资料三类只读材料。确认三专家确实落成指定三条 child；父子共同受冻结任务预算约束，按实际总用量计量。 |
| 完整销售任务 | 同一商机先取证给带来源建议，再提交明确对象的阶段提案；记录人发起批准，最后核对效果和回执。重置夹具后再做独立拒绝。 | 不触发任何客户外联。批准与拒绝均绑定唯一 run/proposal；准备阶段、阶段变更、重读按哪些 run 实际完成分别记录。 |
| 记忆对照 | 1个校准题、正式最多6个任务。覆盖简单、新旧混排超过10条、50/51边界、修改、删除。三臂各执行同一组题；服务异常单独测回退。 | 无跨会话事实、SQL最新10、SQL+Mem0现状重排10。使用生产调用的默认搜索语句及真实 SQL 和 Mem0 适配器；每臂相同候选截止、上下文上限、模型和输出预算。 |
| 执行与观测 | 预定审批竞争、可重试失败、Worker 中断/resume 及拒绝门禁。核查同批已知运行预期的父/专家/执行节点、投递停止形成的积压和恢复。 | 只暂停或终止本批独占的 Worker/投递器，仅在本批测试实例审批和写入。显式记录注入点、重试机会、每阶段时钟和远端读回。 |

模型使用已配置的 DashScope `qwen3.8-flash`。正式调用前确认当前配置与允许的使用额度，冻结每臂实际步骤/上下文限制及请求、token上限。校准先走一题的两臂，正式计划最多32个配对根 Run（12题双臂+4题双臂复跑）；销售限计划的取证、阶段提案和续跑，记忆最多21次模型请求。额度无法核定时先完成不依赖模型的验证，实际调用严格按确认范围。任何越权、错误对象或重复业务效果都停止相关写入并保存证据。

## 计量和留存

- 独立保存每题所需字段、依据 ID 或版本、缺证规则和应发生的动作。运行输入携带任务和授权数据定位，评分答案留在核验器。产品已有规则结果与本批逐项评分分别保存。使用语义 Judge 前先校准；若客观字段和证据已足够，按预定义规则逐项核对。
- 字段正确率分母为预定义必答字段数，缺项算未满足；引用支持率同时报告实际回答引用的支持数/引用数及必须有证据的事实覆盖率，空引用没有比率值；任务通过率分母含尝试及已计划未完成的覆盖状态，分别显示。按同对输出状态、阶段时间、总输入/输出/cache tokens、厂商账单金额或未知、可观测重试和失败归类。子 Agent 默认并发为1，按实际端到端时间核对。
- 执行统计恢复成功数/真实中断或重试数、恢复耗时、效果/活动和回执次数、拒绝后误执行数。按原 `run_id`/job/proposal 对账。观测以预先定义以及SQL事件可推导出的节点集合为分母，检查节点 ID、parent、缺失/重复、积压和恢复耗时，以及投递前后业务/LLM计数。
- 保存合成数据版本、每臂原始结果及可复现运行方法到忽略目录；公开提交任务清单、脱敏结果及计量边界。仅清理精确标记的本批夹具。记忆收益不明时直接记录暂缓。本批汇总先交用户审阅。
