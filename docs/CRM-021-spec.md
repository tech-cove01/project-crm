## 实施与运行边界

本批新实测确认的后续缺陷仍在原目标内：021a2 修待审阶段提前“决定后复核”的模型文档展示；021b2 修父结构化提交超 schema 后缺预算内纠错、知识来源/证据 ID 混淆及专家多读。先登记原因、最小变更和相关验证，旧真实输出及失败哈希保持，不增加 Judge、模型总预算或无关场景。

沿用现有 Pi 0.86.1、DashScope `qwen3.8-flash`、CRM/Worker 和三项本机集成；不换框架、模型、SDK，不操作其他项目镜像、服务、数据。只用已授权合成数据，无真实渠道外发、云部署或追加 Judge。既有组织授权、选中对象校验、确认和来源检查不得绕开。

先根因与相关离线回归，再独立代码审查。产品修复与证据按功能分别提交；真实验证前封存当前源码、资料/版本、输入、预期和自有对象。批准任务使用新提案，明确决定只发一次；不重批旧提案，不对未知副作用盲重放。模型业务、数据库并发与检索验证按窗口协调，防止互相改动相同对象。必要重载仅本仓受管进程。

每次真实尝试保存结果，失败先定位原因再决定对应修复和受影响复查，不以重复同输入挑选成功答案。连接/解析仪器问题和业务失败分列，技术重试保留原报告；越权、错误对象、重复效果或恢复不明先停止该写入并对账，不继续盲执行。完成四项必要验证与独立审查，更新 STATUS/能力及证据后推送，保留实际限制。
