## 场景、预期与顺序

1. **A 授权负例**：跨组织目标、错误目标/参数、inspect 只读、无批准权限。调用现有产品 handler/Schema 和组织范围校验，核对本批对象及副作用计数前后不变；数据库回滚用例、进程内故障注入与真实 HTTP 分别记账。
2. **B 同商机主链**：一个只读准备 Run 读取关联客户、商机和 A/B 产品依据，结论逐项回查；批准与拒绝使用各自新 Run/新提案，决定前无业务变化，决定后重读 SQL 与终答。可拆 Run，不重复提交未知结果。操作者按本次合成数据授权用 API 代发明确决定时如实记录，不称真人点击或人工事实校准。
3. **C 数据边界**：Mem0 超时/不可用仍返回 SQL 事实；旧投影遇同 ID 哈希变化、删除时不返回旧正文。故障注入仅限本批对象，正常产品事实修订用删除旧记录和新建确认事实；不能称已有正文编辑接口。Wiki 改版、撤回、失去授权后旧引用失效；新任务重查。A/B 上固定有答案、无答案、同义改写、冲突问题各一项，结果含来源身份、请求/错误和分母。
4. **D 有界协作**：正常、冲突/过期、局部失败三个切片。正常取证互补不误报；冲突重读消解可继续，未解则持久待复核并服务端阻断依赖动作，人工决定后重新取证；一个子任务缺证/失败时父汇总保留缺口。专家只读，child 结果持久；独立 review 可并发，Mission 仍 `maxParallel=1`。Wiki 仅同一 provider/页/文档/索引身份比较版本。
5. **E 执行恢复**：重复决定或批准/拒绝竞争；已执行但回执保存失败的 uncertain；取消/失租后的迟到执行。限定自有合成任务/注入点，记录副作用次数、回执和续跑。不将租约前置检查称原子 fence，不称外发 exactly-once。
6. **F 观测、规则与 Judge**：各真实业务 Run 精确核对预期 span 与必要评分回读；集成重试不增加模型或业务动作。选择一份短而完整的主链材料单独调用一次 Judge；先确认工具事实及终答进入可见材料，截断或缺证记 unknown。来源人工复核未发生则不称已校准。历史误述/错引/无答案原例作为已曝光回归，不能混入新验证分母。
7. **G 最终独立核验一次**：在固定干净源码 SHA，用本批单独数据和 C 原文检查关键结论，最终结果逐项 pass/fail/unknown/blocked，不推导总体准确率或生产保证。

首轮每个场景一次，失败原文和未知保留；整批最多两轮缺陷修复，每轮先登记问题、原因假设和受影响场景，一问题一提交。修复后只复查受影响场景，同缺陷最多两次，不因分数重跑。Judge 每份材料一次，纯连接/解析失败最多一次有记录的技术重试。最终独立核验硬失败即停止相应通过主张，不自动开启第三轮。

出现越权、错误对象写入、重复效果、不可解释差异或未知结果盲重放，停止相关场景写入并保存证据；到额度或缺必要人工复核则受限结束。保留所有旧失败。云部署、真实客户渠道、自动记忆抽取/衰减、RSI、框架迁移和追加场景不在本批内。其他项目容器、镜像、数据库及用户全局配置不修改。
