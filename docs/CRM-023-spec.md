- [销售](evidence/CRM-022c-sales.md)和[执行恢复](evidence/CRM-022e-reliability.md)已经完成各自有限验证，保留身份、同商机重置、唯一回执和故障点。恢复 2/2 不外推执行中途断电、未知模型请求重试或生产可用率。未改相关代码就不重跑。

复用 `.local/crm022/paired/` 原记录及现有脚本，每项写清触发条件、实际工具结果、判定位置、预期行为和最小修复；不重新执行首轮。当前只读发现：

| 位置 / 原样本 | 需核实并修复的行为 |

新评分必须在调用前冻结并验证正反例：格式合规率；字段正确数/预期字段数；受支持引用数/实际引用数和所需字段覆盖；任务通过数/计划任务数；应答、合理无答案、真正缺证和误复核的分类。空引用分母为 N/A。服务 unavailable 不能当正常无答案；事实正确但没有必要依据，不算有据任务通过。缺证题是否允许 partial 由该题预期决定，不以一律 completed 当成功。

校准最多 2 个已知题，优先 X02 的取证恢复和 M03 的正常空结果。正式已知回归固定四类各 1 题，建议 S02、X02、C01、M03；这些已用于诊断，不称盲测。另冻结四类各 1 个新的保留任务，使用新问题组合或证据关系，不能只换对象 ID、姓名或金额。真值及评分由独立审查者核对，不注入模型或在调参时查看新任务表现；一旦用于调参就标为已见，不再追加题目凑保留集。

## 023b–c：有限修改，再给可解释的结果

1. 优先修政策角色的当前任务范围和证据状态判定。明确的检索词应被忠实使用；若需回退，只复用已有有界检索，不引入新的查询规划框架。正常空结果只有在任务允许确认“没有资料”时才支持受限回答；若任务必须依赖政策作建议，真实缺证仍阻断。后续命中必须确实补齐同一要求，不能拿无关材料清掉缺口。
2. 每个缺陷做独立小提交及直接相关验证。至少覆盖无关职责、正常空、先空后命中、无关命中不能补缺、服务/授权失败、真实冲突和业务写入为零。尽量复用现有 collaboration、result submission 和 review 测试。涉及持久复核或动作准入时补真实隔离 PG 验证，原有拒绝、旧提案失效及并发保护不得退化。
3. 最多两轮代码修复和校准。校准达到“有据正例可交付、正常无答案可正确受限回答、真正不可用/越权/未解冲突/必需依据缺失仍受阻”的诊断目标后冻结版本进入正式批次；若两轮后仍有系统性阻断，保留受限结果并结束这一方向，不浪费正式整批调用重复已知故障。其他方向照常完成。
4. 正式八题双臂各一次：同一模型、任务、资料、权限、温度及总预算规则，使用独立等值商机避免复核状态串臂，交替执行顺序。单 Agent 可取得同等材料，三专家限制来自实际产品职责。父子用量合计；检查每个三专家根确有三个预期子任务。**本批保持 `selectCollaborationPlan` 自动路由不变，三专家用现有 `auto`，单 Agent 用 `disabled`；只修专职任务与证据处理，不新增强制接口或通用分类器。** 简单任务按实测结果推荐现有单 Agent 模式；若某根实际退成单执行，记录布局不符，不能计作三专家通过或重新运行替换。
5. 已知四题列原版→修后，新保留四题单列单 Agent/三专家，绝不拼成“未见八题”。保留原严格成绩；如用新版兼容引用规则对旧数据离线重算，另给方法校正表，不与产品改善混为一谈。每类分别报告正确字段、引用、任务、误复核、正确受限回答、端到端耗时及 token；中位数和每题原值同时给出，不凭小样本报稳定 P95 或统计显著提升。
6. 若三专家仍无优势、相当但更慢或 token 更多，结论就是这些任务优先单 Agent。三专家的分工与复核机制可以保留，但不写成已验证质量提升，也不自动加更强模型、更多专家或第三轮调参。

## 调用预算与停止条件

| 范围 | 最大额度 / 约束 |
| --- | --- |
| 根因、评分检查及记忆 | 零新模型。记忆不扩样本，不重构。 |
| 协作校准 | 2 题×2 臂×最多 2 轮，最多 8 根。修复一次有效即可结束，不用满。 |
| 正式协作 | 8 题×2 臂，各一次，最多 16 根，不设额外复跑。共最多 24 根、最多 36 个专家子运行，子运行不是额外免费额度。 |
| 单任务规则 | 沿用 `dashscope/qwen3.8-flash`、12 步/36,000 token，父子共同计量。核验现有 child 分配和父预算扣减；保留轮边界检查/并发下可能超出规则的实际值，不称硬限额。 |
| 仅在审批/恢复门禁被修改时 | 复用既有隔离脚本，至多批准、拒绝各 1 个新根及各 1 次续跑，沿用 8 步/16,000 token，最终仍核唯一效果/回执及决定后重读；否则不执行。 |
| 整批用量 | 沿用旧配对执行器的 750,000 已报告 input+output 停止门槛与每次开跑预留检查，涵盖父子、校准、条件回归及 Judge。cache read/write 另列，未知不填 0；缓存不计入该历史停止口径并不表示无成本。达到门槛不再开新任务，所有已开始任务及超量如实记录；非厂商金额或绝对硬上限。 |
| 观测 / Judge | 观测不新建业务/模型 Run。规则评分默认不调用模型；只有确有规则不能裁定的语义项时，先固定材料及 rubric，最多 2 次 Judge，作为辅助分列，不能替代规则或把高分当真值。 |

不以账单未知阻塞已授权的有限调用。网络/提交结果不明时只读对账原 Run，不重新创建撞运气；模型失败、缺证或错误答案算已用额度并保留。只有在创建前被证实没有发送模型请求的仪器错误，才可修采集后继续原计划，不增加任务。超范围写入、错误对象、重复效果立即停止相关写路径，保全证据并报告，不能以消耗剩余额度继续。

## 023d：让观测在选定本机配置下可复现

- 复用 [本机集成 Compose](../infra/local-agent-services/compose.yml)、ClickHouse 低内存配置、[导出器](../lib/ai/integrations/langfuse.ts)及[回读](../lib/ai/integrations/langfuse-readback.ts)，不另搭平台。先检查实际可用内存、服务峰值、ClickHouse/cgroup 限制和插入批次；选最小可行配置或限速方式，保存重启方法和适用负载。选择扩容时固定可再次使用的本机配置，不能临时修好、恢复已知不足的配置后又宣布稳定。不得重置卷或更改其他项目/全局 Docker 配额。
- 用 CRM-023 已计划的 Run，或首轮尚未投递的事件，冻结两个**不同 root 集合**的事件清单和各自预期节点；每批投递前回读确认目标节点尚不存在，不能仅凭事件 ID 不同或回读旧 59 节点检验新投递。总负载至少包含一条三专家父子链；每批至多 15 条原 spans 事件，若比首轮更小需明确负载边界。
- 023c 开始前协调两个投递窗口，优先采用“首批生成并验收→暂停本批独占投递器→后续已计划 Run 形成第二批积压→冻结清单→正常消费者恢复”。消费者可能一次排空已有积压，不能预先把两批全放进队列后假定第二批仍未投递。仅复用现存积压时，须证明既有消费者能停在批界；无法形成两个独立首次投递窗口就如实记录覆盖不足，不额外创建模型 Run 补数。不暂停业务 Worker，不修改正常业务执行或新造业务事件。
- 每批最多观察 10 分钟，最多两次配置尝试；按 ID 核对节点数/父链、错误、死信、积压及恢复耗时，记录实际峰值。一次明确缺失的原事件可按现有工具稳定 ID 补投，另列人工恢复；不能把人工补投写成自动恢复。验收末对至多 1 条原事件重复投递核对远端无重复节点、业务/模型无新增。
- 补齐本批评分关联：从这些既有 Run 选至少 2 条（一条正常、一条受限/失败；本批没有失败时使用已保留的首轮失败并注明），通过既有[评价路由](../app/api/v1/ai/workbench/runs/[id]/evaluation/route.ts)的 `deterministic_export` 导出 CRM 规则结果。核对 score ID、名称/值、trace/run 对应关系和规则版本；错误或 needs_review 原样保留。逐题对照评分与产品 Eval 的分母不同，不冒充同一准确率。
- 同一抽样核对远端模型节点的开始/结束、duration、usage 与 CRM 实际发出的 payload；聚合 `llm_calls` 与逐模型节点不强作一一对应，cache/未知金额分别报告。59/59 是追踪完整度，不是答案正确率；未调用 Judge 就明确未验证本批语义 Judge。
- 若本机在有限尝试后仍无法支撑，标明“观测受资源限制，原事件可人工恢复”，给出可复现配置/处理办法并停止。协作效果和记忆结论不因此作废，不自动转云、不购买资源。

## 023e：验收与最终事实汇总

每批完成后由独立审查者核对变化范围、原始结果和停止条件，更新 STATUS、必要验证后单独提交推送。通过才勾完成，失败可按“受限结束”结票但不能称优化成功；不将 Git 提交或 HTTP 200 当验收。

最终 `docs/evidence/CRM-023-summary.md` 按以下项目交付给用户，供另一位简历 Agent 自行选材：实际做了什么、解决了哪个具体问题、关键设计和替代方案、样本规模与指标定义、旧版/修后/保留集各自结果、逐任务耗时和用量/金额未知、失败与适用边界、产品代码/运行配置/原始报告位置。明确区分“已经测得”“只有功能验证”“仍未验证”，保留 CRM-022 首次失败及仪器修正，不重复相加不同批次的分母。

验收末确认测试库队列、尚未明确的任务和自有进程；不动其他 Agent 的服务或未提交文件。记忆保留现状、销售恢复复用原证据；到达既定轮数后不再扩功能或追全绿，交付事实和限制即可结束。
