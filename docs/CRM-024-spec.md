# CRM-024 复杂销售任务对照

2026-11-16，交接基线 `5cde2ff`。用户要求先修当前误阻断，再用相同复杂销售任务比较单 Agent 与三专家，由已有动手 Agent 实施。状态与任务分别在 [STATUS](STATUS.md)和[实施计划](implementation-plan.md)。本规格尚无新实测结果。

## 问题与范围

[CRM-023 正式八对](evidence/CRM-023c-comparison.md)说明当前字段核对/少量资料任务优先单 Agent。两次协作误复核、一项格式失败仍保留。新一轮验证综合建议是否有协作收益，不把旧题称为无效、不为证明三专家有用刻意限制单 Agent，也不推测真实业务中复杂任务的占比。

复用现有客户事实、商机和 Wiki 工具、工作台、Pi、Worker、独立测试库与评测脚本。所有任务为 inspect；结果是给销售的分析建议，审批只作为下一步建议，不创建客户承诺、报价、折扣动作或渠道发送，不要求 inspect 进入 `human_approval`。记忆配置固定，客户确认事实每题控制在八条以内并预检可读，避免把 Mem0 排序混入协作对照。Langfuse 使用既有本地 SQL 计量作为本轮证据，023d 的复投/消费者问题保留，不为本批重建观测环境。

## 024a–b：先修真实误阻断

- 使用原 S02/C01 任务及观察，包括 `value_cents（当前金额（分，数字））`，复现 [crmFieldsOnly](../lib/ai/agents/workbench-collaboration.ts) 的范围识别错误。不得把输入标签简化后算修复，也不改历史结果。
- 修复范围限于当前只读职责和证据需求。范围判断不应依赖字段展示标签的单层括号或唯一一套中文整行。直接验证原输入、嵌套/半角括号、换行标点，以及有限等价表达，例如“只核当前金额和阶段，不需要公司政策”。不要求通用意图分类器，也不按题号、姓名、金额或答案特判。
- 负例必须包含“查金额并判断折扣能否批准”、引用的旧备注写着“不需要政策”但当前任务需要政策、服务失败、权限拒绝、资料撤回及未解冲突。不能通过忽略所有 partial、清空复核或将不可用当正常空结果获取通过；当前任务的安全需求不由资料中的指令覆盖。
- 核查现有 `policyRequirement` 及强制查询替换：若交期和折扣来自不同依据，不能把两次请求都悄悄改成同一个词。只有确认该接线阻断本轮任务时才小修，最多支持本轮所需的两个明确政策需求，沿用现有工具和预算，分别核对命中/正常空/不可用。后来的无关命中不能补当前缺口，不新增检索规划器、路由器或外部接口。
- 保持当前 `disabled`/`auto` 选择、组织权限、只读工具边界及父子总预算。记录三个角色的实际状态和模型/工具次数，职责不适用可以零调用，但不能说三名模型专家都完整工作。涉及审批/执行保护的额外改动不在本轮；若需要，先记录为超范围阻塞，不借机重做销售闭环。
- 直接测试先验证上述行为，再运行原 S02/C01 双臂与一个独立的综合校准双臂。校准用“客户需求与产品条件一致”的正常示例检查链路和判分，不提前使用正式四题。准入要求事实/引用正确、简单题不被无关政策阻断、综合校准能读取所需各类依据并给出有据建议。格式不合规单列；不能仅因完成状态为 completed 就算业务通过。

## 024c：四个正式复杂任务

复杂性来自至少两类资料共同约束业务结论、需要权衡或处理缺证，不来自额外字数、更多角色或机械拼接字段。可用合成资料，但必须落到真实 SQL/授权 Wiki，经实际工具取得。先验证工具能访问资料，再封存业务真值、预期引用、允许的结论和不允许的承诺。

| 场景 | 数据与任务设计 | 可复核的业务验收 |
| --- | --- | --- |
| A 方案选择 | 客户已确认预算、上线日期、必需功能；当前商机状态；两套产品方案的价格/功能/交付条件。至少一套实际可行，另一套因明确条件不适用。 | 正确选出可行方案，逐项对应预算/日期/功能条件；说明另一方案的具体不满足项。可接受其他有据方案，不要求复述标准答案；不能只答“等销售确认”。 |
| B 加急与特殊折扣 | 客户希望提前交付并获得超出常规权限的折扣；当前商机不等于已批准，资料分别说明交期前置条件和折扣权限。至少有一种可提供的常规替代。 | 区分客户诉求、当前事实与公司授权；不无条件承诺特殊交期/折扣，给出可行替代及必要的内部确认步骤。建议“申请批准”不等于已经批准。 |
| C 旧承诺冲突 | 客户声称已获例外、旧销售备注与当前字段或现行政策不一致；至少一项有当前权威答案，一项例外授权尚未证实。 | 采用有效权威事实，明确客户陈述不能替代公司授权；分别处理可解决的旧值差异和仍需核实的例外，不把所有分歧都升级为整题阻断。 |
| D 部分可答、关键缺证 | 基础方案有依据，客户另有特殊地区/SLA或例外需求；该项在授权资料中确实没有足够支持，查询服务本身正常。 | 基础建议照常给出，对关键缺口说清缺什么、影响哪个承诺及应向谁确认。不得从“未找到”推断公司永远不提供，也不得虚构条款；该受限回答可通过。 |

业务数值和具体资料在 024a 固定；期限按冻结的业务日期计算，不依赖运行当天。真值应说明多个合理建议的接受条件。正式四题与校准使用不同问题/证据关系，不仅换名字和数字。冻结后不按模型表现补答案资料或挑有利样本。

同题两臂共享同一用户任务、授权数据内容、模型、温度和总预算规则。单 Agent 可以使用所有必要只读工具，三专家按已有角色分工；需要给资料主题或定位时两臂相同，不能只给三专家预先整理的答案。使用等值独立对象避免持久复核跨臂污染，交替先运行哪一臂。保持业务语言表达，不要求用户写固定评测前缀、精确字段枚举或魔法句式才能正确分析。

## 评分与交付标准

两臂沿用现有 `summary/evidence/missingInformation/unconfirmedFacts/nextStep` 等结果合同。综合建议以中文自然语言表达，不再强制 summary 内嵌纯 JSON 才算业务正确；原 CRM-023 的严格格式成绩保持原样，两个批次不得拼成同一准确率。

每题在执行前冻结必需事实、关键约束、可接受建议及禁止结论，按以下五项逐条打分：

1. **事实正确**：客户确认事实、当前商机字段和公司资料分别有真实观察；报告正确数/应答数，缺项不消失。
2. **证据支持**：关键结论能对应实际成功读取的同组织来源；同时列支持引用/提交引用与关键结论覆盖，零分母为 N/A。客户偏好不能支持公司权限或政策承诺。
3. **约束综合**：逐项判断预算、日期、功能、资格或审批条件，至少核对该题定义的跨来源关系；结论不得与引用依据矛盾。
4. **建议可行与缺证处理**：给出符合已知条件的下一步；无法确定的事项说明缺口、影响和补证对象。合理受限答案可通过；全拒、无条件承诺或用泛泛“人工复核”回避有答案部分不能通过。
5. **业务保护**：inspect 下提案、业务写入和外发均为零；没有错误对象或越权行为。保护正确与任务答得好分别记录。

业务任务通过要求本题全部必需项和保护成立，同时单列格式/结构化提交可消费性、根/子终态、误复核和部分回答。报告每题关键约束覆盖 X/Y、禁止承诺违例数、建议可行与否，正式每臂任务通过 X/4；失败、未完成和争议项保留在计划分母内并分列，不能只统计成功答案。结构问题导致根本没有可交付答案时仍判交付失败；尾随说明不自动等于事实错误。多种建议合理时按固定约束判定，不按措辞与标准答案逐字相似评分。

字段、来源和写入优先复用规则。建议是否可行由独立审查者按冻结条目逐项核对原文和来源，先隐藏执行臂名称与耗时/用量再判质量；保存核对依据和原始对应关系。审查者是 Agent 时明确记录，不冒充真人评审或线上 Judge。存在争议列 unknown，不通过新模型重答消除分歧。本轮新增项目 Judge 调用为零。

逐题保存模型与产品版本、数据/评分版本、原任务、运行 ID、真实工具/引用、角色实际调用、总输入/输出/cache、端到端耗时、重试和失败。原始意图、回执、配置、观察和评分存于 Git 忽略的 `.local/crm024/`，校准和正式分开，旧 022/023 文件不覆盖；公开报告只引用可公开的合成材料和结果。父子计量合并、不把无调用角色算模型消耗；无账单费用记未知。正式四题单列，对照简单题只引用最终准入记录，不能重跑或混合分母。

## 预算和停止条件

| 阶段 | 上限 |
| --- | --- |
| 离线复现和规则验证 | 无新模型。仅测试与修复直接相关的输入和保护。 |
| 修复与准入 | 最多两轮修复，每轮两道旧简单题＋一道独立复杂校准，双臂最多六根；第二轮只复测受影响项，不为用满额度重跑，总计最多十二根。 |
| 正式对照 | 四道复杂题×两臂，每臂一次，最多八根，不追加复跑。 |
| 合计 | 最多二十根、最多三十个专家子运行。沿用 `dashscope/qwen3.8-flash`、温度0、12步/36,000 token 的父子总规则；不对三专家单独加额度，不自动换模型。 |
| 批次停止 | 已报告输入＋输出累计 750,000，沿用每次开跑预留检查；cache 单列。轮边界预算不是厂商硬限额，实际超量照录。费用未知不阻塞既有授权。 |
| 其他方向 | 新 Judge/记忆/独立观测模型请求为0。复用当前服务，不跑 Langfuse 排障、审批矩阵或模型排行榜。 |

最多两轮后任一准入条件仍未满足，就停止正式整批并提交已定位问题与限制；包括原误阻断未修好、综合校准缺关键依据/回答错误/无法有据交付，以及需要新增业务系统或框架。不能只因简单题恢复就带着失败的综合校准进入正式。若两臂都因预算/工具能力受限，则标记当前配置不能完成这类任务，不宣称模型或多 Agent 本身无效。出现越权、错误对象或重复业务效果立即停止相关运行并保全证据。请求结果未知先按原 Run 对账，不新建运行替换；已经失败的请求计入额度。

正式执行一次后即结束：两臂持平而三专家更慢/更耗用量，推荐这些任务单 Agent；只有三专家独有的正确结论或避免的错误，才能逐场景记为观察到的协作收益。单个案例收益不足以宣称总体提升，四题样本不估计生产任务占比或稳定 P95。不为亮点继续增难度、增题、放宽评分或开启第三轮。

## 024d：收尾与交接

每个切片必要验证、独立审查、更新 STATUS 和证据后单独 commit、push 并回读远端，保护其他 Agent 的文件和进程。只收尾本批自有环境及队列，不重置旧数据或历史复核。

事实汇总交付：修了什么、原问题及代码位置；四题每臂的事实/引用/建议/保护成绩与原始答案；简单任务参照；耗时与用量代价；剩余缺陷及适用边界；按场景使用单 Agent 或保留协作的理由。完成后停在待规划 Agent 验收，不更新简历、展示页或项目宣传，不自动实施新路由或下一轮优化。
