# CRM-025：先冻结业务样例，再验证通用检索与协作效果

2026-11-16。用户要求扩大实际业务场景覆盖，先冻结例子和评分、测现状，再修改代码并复测，避免只迎合已知失败题。接续产品基线为 `2d5d411223e68fef47a41c064040baf6d7c4056d`。沿用现有工作台、Pi、Worker、SQL、客户事实与授权 Wiki，不建设新评测平台。当前状态见 [STATUS](STATUS.md)，任务见 [实施计划](implementation-plan.md)。

## 现状与待验证的设计判断

- CRM-022 有 12 道正式题；CRM-023 有 8 对，其中 4 道为旧题、4 道为新增保留题，不能相加宣传为 20 个不同场景。CRM-024 实际运行 3 道校准题、两轮共 11 个根；原 4 道复杂正式题没有运行。当前证据主要是字段核对和少量资料组合，不足以证明复杂销售任务的普遍收益。
- 已修复简单任务的无关政策阻断、商机专家不读所选记录便结束和未选会话的工具暴露。第二轮简单题两臂均 2/2。复杂 K01 两臂仍失败，正式 0/8。原记录保持，CRM-024 按受限结果验收，不再反复补其“第三轮”。
- 已有一项可离线复现的局部设计问题：`weknora.ts` 的回退候选经过 `supportsWikiQuery` 全词面覆盖过滤，客户情境、问法或同义词可能把相关材料排除；全词出现又不能证明结论成立。六条旧查询只能用于定位和回归，不能作为新版本泛化成绩。
- 新一轮将**候选材料相关性**与**结论能否得到证据支持**分开。允许找到相关保修资料但回答“未找到自动续约条款”；不将“有相关资料”误算为有答案，也不为了拒答把全部相关资料过滤掉。修复要经过新场景验证，不能预先宣称方案已经有效。

## 已编写的场景与冻结边界

[业务场景数据](evaluation/CRM-025-cases.json)包含 24 个不同业务场景：8 个开发诊断场景、16 个未用于修复的保留验证场景；[阅读版清单](evaluation/CRM-025-cases.md)列出具体问题和预期边界。共 31 篇完整合成材料，23 个知识任务各三条问法、合计 69 条检索探针，D01 纯 CRM 核对不强制检索。均为用于真实系统的合成客户、商机和企业材料，非预设成功回答。每题提供实际用户任务、业务字段、确认事实、来源正文与状态、相关材料、必需结论和禁止结论。

场景数、问法数、工具请求数和 Agent 运行数分别统计。三个问法不等于三个独立业务场景，重复运行也不能增加样本量。题目的开发/保留划分在测量前固定，保留集的证据关系和业务约束须有差异，不能仅换姓名和金额。

本轮先冻结**语义数据文件与评分约定**。实施 Agent 随后将相同内容落入隔离 SQL/Wiki，并在真实调用前追加环境冻结：实体映射、资料版本和正文哈希、租户与角色授权、实际可用工具、模型/温度/提示词、步骤及父子预算、产品代码版本、评分与执行脚本版本。冻结业务日期和合成工作日日历须实际提供给两臂，不能只存在评分答案里。未落库、未运行时不得写成已完成数据环境冻结或实测。

逻辑材料 ID 要映射真实 CRM 来源和知识库，不能假定当前产品已有逐页 ACL。28 篇本组织当前发布材料形成各题共同的候选池，不得只授权每题的预期答案文档。异租户材料在独立组织/知识库中，旧版和撤回材料用真实版本/撤回机制处理；不得把它们混入同一可读知识库再靠评分忽略。正确映射多篇同权限页面，避免现有最多遍历五个 CRM 来源的限制导致材料静默漏装。这仍是小型合成语料，不代表大库检索能力。

基线是当前产品代码；为了执行新评测可新增薄脚本、种子和采集适配，但不得在基线前改查询、提示词、工具接线、来源筛选或业务保护。脚本与产品的哈希分开记录。发现夹具错误须先改正并重新冻结相关批次，不能将缺资料的环境问题算作产品质量失败；已有真实调用及其费用记录保留。

## 开发集与保留集的使用

1. 开发集用于观察基线、定位问题、编写直接回归及选择通用修复。旧 022–024 已见案例只作回归，不混入本次保留集指标。
2. 保留集题目规格在仓库可见，所以只称“未用于调参的保留验证集”，不宣称题目完全隐藏。由独立评测 Agent 执行和封存其基线逐题结果；实施者在候选版本固定前只得到完成数、环境/安全异常，不查看具体质量分、答案或错题来调整实现。
3. 保留集的修前、修后原始结果直到候选版本和评分冻结后一起解封。若实施者已据这些结果改过代码，如实标记污染并降为回归结果，不悄悄换题或将其继续称为保留验证。
4. 同一题的问法变体属于同一分组，不能一个问法放开发集、其同义改写放保留集。所有真实作答模型只能收到用户任务、允许的业务上下文与真实工具观察，不能收到预期答案、评分条目或开发/保留标签。

## 执行顺序：质量失败不能挡住整个测量

### 025a：落库、独立审查、冻结

先审查 24 题是否可由现有能力表达、证据与真值是否一致，尤其金额单位、工作日、否定/条件句、旧版与当前版、客户陈述与公司授权。实际落库与配置冻结后，正例由受测身份用真实授权接口**按资料 ID 回读**证明材料存在且版本正确，核对选定客户事实。旧版、撤回和异租户负例由隔离夹具管理者独立证明存在与状态，受测身份应拒绝/不可引用，不能为了预检而提升权限。不能要求自然查询先搜对、Agent 先答对才准入，那会遮蔽本来要测的缺陷。

将工具权限审计绑定实际挂载工具及对象范围；不得继续使用漏掉合法列表工具的固定七项名称表。区别合法只读调用、已拒绝的错误请求、实际范围外返回和未知效果。预期拒绝、合理空结果和答案缺证是要测的业务结果，不是环境未就绪。

### 025b：先跑当前版本基线并封存

- **检索层：** 每条适用探针经真实 CRM 适配器读取授权 Wiki，保存输入、候选/原文回读/过滤原因和最终返回。与 Agent 模型调用分开记数，不拿本地字面模拟替代真实适配器结果。
- **任务层：** 24 题各单 Agent、三专家一次，共 48 个根。开发集 16 根可用于诊断；保留集 32 根由独立评测 Agent 封存。照常记录三角色实际工具/模型次数，不把零调用角色当成三次完整模型工作。
- 每题两臂内容相同、目标对象等值且相互隔离，交替先后顺序。前后版本分别使用等值独立对象，避免待复核状态、记忆或先前运行污染。每题确认事实不超过既有读取边界，记忆模式固定，不在本轮测 Mem0 优化。
- 普通漏召回、事实错误、格式问题、partial、合理拒绝和步骤封顶均保留为该题结果，继续其他安全题。只因环境不完整、效果未知或实际越权等确有阻塞才暂停相关调用。**没有“所有校准通过才跑正式题”的质量门槛。**

### 025c：根据开发证据做一次通用修复

基线封存后才修改产品。按错误类别处理候选资料召回、结论支持、金额单位或已证实的工具接线；每项变动说明对应的业务契约与反例。可使用通用标题定位、有限查询归一化或现有召回排序，但不得硬编码例题标题、题号、金额、预期结论，也不能只把旧六条查询的失败词加进停用词表。

不要求保留错误的实现细节：原“必须每个词在同一页出现”或“英文只做整句匹配”的测试可以按新业务契约改写。必须保留授权隔离、版本/撤回检查、原文回读、引用归属、请求上限与读写/审批保护；不能以召回提高为由把这些检查删除。原用例、不同词汇和证据关系的开发反例均参与直接验证。

离线修复和必要测试可连续进行；不要每修一个词就重跑模型。完成代码审查后冻结一个修后候选版本。开发集的整套真实复测只跑一次；保留集结果不得作为继续调参的反馈。出现新缺陷如实留下，不自动追加第三版本、换模型、加专家或引入新检索平台。

### 025d：同题复测、独立判分、交付

相同检索探针和 24 道业务任务在修后各运行一次，两臂、预算、真值与评分规则保持一致。解封保留集基线，按题配对比较。报告至少分开发/保留、冻结的 `reportGroup`（基础核对 2 题、约束综合 10 题、缺证或冲突 8 题、权限与不可信输入 4 题）、答案充分/部分缺证/无答案，以及单/三专家；不将这些类别揉成一个漂亮的总分，也不在看完结果后重新分组。

任务通过不是唯一完成条件。即使修复无收益、回归或三专家仍更慢，也要交付完整分母、原始失败与结论。最终停止在待规划 Agent 验收，不修改简历和宣传材料。

## 两层真值与评分

| 层次 | 要测的内容 | 不能混淆的边界 |
| --- | --- | --- |
| 候选资料 | 固定 top-5 探针的应取回资料覆盖、全必需资料命中、相关/无关候选、已授权且版本有效的回执 | 有相关页不等于问题已回答；没有答案但有相关资料时，允许返回该页并说明缺证。无应召回资料的分母记 N/A，另看无关材料是否被冒用。 |
| 业务答案 | 必需字段/金额单位/日期是否正确，关键结论支持率与覆盖率，约束综合、建议可行、部分可答与缺证处理 | 不能只检查预设字段而忽略影响决策的额外无据事实或承诺；真实的拒绝、空结果和运行状态不属于幻觉。 |
| 保护与交付 | 对象/组织权限、当前来源、提案/写入/外发、可消费结果、错误尝试及实际效果 | 被拦截的错误尝试与实际越权分别统计；inspect 的“需要批准”是建议，不要求生成真实审批或外联动作。 |
| 成本与效果 | 每题端到端耗时、工具次数、根及子任务输入/输出/cache、失败/重试；实际账单缺失则未知 | 追踪完整率不等于答案正确率；不把无调用角色算模型成本，不把此次业务执行设计收益归为 Pi 框架本身。 |

字段/来源/执行效果优先由真实观察的规则复核。自然建议和额外断言由独立 Agent 按固定标准审查；匿名包隐藏执行臂、代码版本、耗时和用量，但保留完成判断需要的事实、资料、业务日期、成功/空/拒绝回执及只读效果证明，使用中性别名。先检查评审包未漏证，再判模型无据；审查者身份如实写 Agent。无新增项目 Judge 调用。

业务通过要求本题必需事实、证据、约束、建议/合理缺证与保护成立，额外的重要错误或未经支持的承诺不能靠必需字段满分抵消。格式独立列出；只有格式导致无法交付时才同时判交付失败。规则、基线与修后使用相同版本，纠正评分器错误应对两版本统一离线重算、保留原判，不靠模型重答修分。

## 调用范围、恢复与停止

- 业务任务总量固定为 **24 场景 × 2 模式 × 修前/修后 = 96 根**；其中开发 32 根、保留 64 根，三专家子任务最多 144 个。不是要求跑到全部通过。69 条检索探针修前修后各一次，共 138 次顶层适配器请求；内部 HTTP/索引调用另记，不虚称所有检索成本为零。
- 保持 `dashscope/qwen3.8-flash`、温度 0、原 12 步/36,000 token 的父子预算规则及同等权限。本批已报告输入＋输出上限为 4,000,000，cache 单列，开跑前按既有方式预留并将实际超量照录；不隐式继承旧批次的 750,000 阈值。已有 022–024 费用与结果不重置；本批单独累计真实用量，不增加与比较无关的审批、记忆、观测或 Judge 模型调用。
- 原请求结果未知先按意图和 Run 对账，不新建“替代成功”。普通任务失败不重跑；明确采集故障只补读原结果。调用前发现夹具错误可修正重冻；调用后发现的配置事故须保留为 `invalid_environment`、计入 96 根上限并说明缺失配对，不能新建 Run 顶替原槽。必要环境修复只影响后续未运行槽，记录版本变化，不混称同条件完整对照。不得为获得好数字换数据、加版本或追加额度。
- 只有实际范围外数据/写入、原执行效果无法确认、外部账号或服务确实无法恢复、不可避免的并行改动、达到本批调用上限或必须扩展既定业务范围时，暂停相应调用并报告具体阻塞。其余独立工作继续，完成证据、状态与提交推送。权限故障与期望的权限拒绝区分。
- 每批独立审查、更新 STATUS、commit/push 后自动进入下一批；无须逐阶段重新请示，不在一次题目失败处收口。对照结束即交付，包括无收益和未运行项，不继续第三版调参。
