# CRM-026：客户跨会话记忆与独立泛化补测

2026-11-17（Asia/Shanghai）。用户已要求将仓库外备忘转为清晰的执行计划。来源为共同工作区 `.reviews/crm-planning/2026-11-16-memory-generalization-followup.md`，本规格已完整承接所需范围，独立克隆无需该本机文件。当前任务和勾选进度分别见 [STATUS](STATUS.md) 与 [实施计划](implementation-plan.md)。

## 目标与固定边界

先用原证据收尾 CRM-025 的判分缺口，再回答两个新问题：同一客户在新会话中能否正确使用、更新或撤回已确认事实；固定当前产品能否处理独立的新客户、新资料及表达/条件变化。CRM-025 的开发及已解封保留材料均视为已见回归材料，不再称新验证集。

复用现有 Pi 工作台、SQL、Mem0、Wiki、执行与采集脚本，只新增本轮夹具、必要评分适配和汇总。不换模型/框架，不开发自动事实抽取、记忆衰减、商机级记忆、新路由或新平台；不扩大审批、恢复、Langfuse 或三专家优化。README、正式简历和素材保持。

冻结当前产品运行树（现有候选 `1561dac`；开始前核对交付后是否有产品变更），模型沿用 `dashscope/qwen3.8-flash`、温度 0、inspect、12 步/36,000 token 规则。全部新任务固定 `collaboration=disabled`，核验实际专家数为 0。真正的跨会话来自产品记忆读取，不通过把旧事实拼入题干模拟成功。

## A. 先离线补齐 CRM-025，模型调用为零

## B. 冻结环境、场景与评分，先做无需 Agent 生成的真实预检

### 记忆三组的实现口径

- 三个隔离组织（或有等价隔离证据的专用进程）分别承载“无持久确认事实 / SQL / SQL＋Mem0”。三组共享语义相同的客户事件、当前问题、模型和预算，实际实体与远端投影分开，防止更新、删除或待复核状态串组。只配置本批自有 Web/Worker，不修改共享服务或用户全局配置。
- 无记忆组保留同样的前会话业务原话，但不持久化确认事实；后续会话不加载该历史。明确这是评测控制条件，不宣称产品已有一键关闭记忆开关。SQL 组正常确认事实但无 Mem0 绑定；Mem0 组在进程绑定和数据库启用配置均就绪后使用真实同步与查询。
- 事实只经现有入口确认或撤回。当前没有正文编辑 API；更新使用 DELETE 旧事实再 POST 新事实，并说明两步非原子。PATCH 用于外部请求对账，不能当正文更新。直接 SQL 修改若用于故障夹具，单列为适配器探针，不能冒充用户更新流程。
- 每个检查点创建新的 conversationId 和 Run，前序检查点仍属于同一客户轨迹；不得沿用旧 checkpoint、结果或消息上下文。所选会话只含本轮不泄露答案的请求，历史事实应从真实 `crm_get_contact` 等现有工具返回。检查实际初始 messages 和工具观察，不能只看会话 ID 不同。
- 事实不得同时泄露在商机描述、组织记忆、系统提示、知识库或题干中。客户级偏好不等于公司政策、商机事实或外发授权；未实现的更细粒度归属能力记录为限制，不临时扩数据模型。
- 保持 SQL 最近 50 条/返回 10 条及现有默认检索文本，不将题目答案或定制 query 塞入 Mem0。评分接收 `status=local/mem0/local_fallback`，将其与 `coverage=complete/partial` 分开。无记忆组诚实留空、SQL 回退成功及有记忆任务完成分别计数。

### 最小正式样本

记忆共 **3 条语义客户轨迹、6 个检查点，每点三组各一次，共 18 根**。等值实体按组复制不增加独立客户轨迹分母。

| 轨迹 | 检查点 | 主要验证 |
| --- | --- | --- |
| M-A：客户事实变化 | A1 初次确认后的新会话；A2 撤回旧值并确认新值后的新会话；A3 撤回偏好后的新会话 | 稳定偏好及事实使用、改口后当前值、删除后不复活旧值；A2 保留未变偏好，避免把所有历史一起清空 |
| M-B：事实选择 | B1 超过 10 条候选中的较旧相关事实及另一条近期事实；B2 不依赖客户记忆的任务 | Mem0 相对 SQL 的增量、近期事实不被挤掉、不相关记忆不干扰答案；不要只测对 Mem0 有利的题 |
| M-C：归属与用途 | C1 同名/相似描述客户并存时的定向建议 | 仅使用所选客户事实，客户陈述不升级为公司授权；跨组织保护另做无需 Agent 生成的探针 |

每条轨迹的具体事实、事件顺序、可答/不可答项及预期结果在真实调用前固定。M-A 可以同时使用沟通偏好和预算，但本轮问题不能再次给出要检索的值。

50/51 窗口、旧投影删除/修订、跨组织拒绝和一次 Mem0 不可用优先复用 CRM-022 已验记录，并在本轮环境用真实工具/数据库补做无需 Agent 生成的必要探针：至少确认当次绑定、状态与回退契约。故障由本批专用进程/传输边界注入且保留记录，不给共用 Worker 替换全局 fetch。窗口外未猜造和重要事实无法召回分别记录，不扩大窗口。旧投影无法通过现有入口保留时注明复用证据和未重验边界，不搭假 Mem0 服务。

### 泛化样本

由独立样例准备者按业务约束设计 **6 个新资料/客户家族，各 2 个相关任务，共 12 根**。在准备前固定被测产品，准备者不照着词表、阈值或当前错题逐项配题；样例、语料、评分经独立审查冻结后才调用。题目可含正反例、部分缺证及无答案，不全选可答或复杂题。

| 家族 | 两题间应检验的关系 |
| --- | --- |
| G1 同义表达 | 业务含义相同、用词句式不同，核心结论保持 |
| G2 无关干扰 | 增加/调整无关上下文或资料顺序，关键事实与结论保持 |
| G3 约束改变 | 预算、交期或适用条件有实质变化，方案与结论应相应改变 |
| G4 授权条件 | 有明确批准前提与无条件许可的区别，不能混用客户意愿和公司政策 |
| G5 相关不等于有答案 | 主题、数字或单位容易混淆，一题有据，另一题缺所问属性；检查错引和无据承诺 |
| G6 真正无相关资料 | 一题可答、另一题库中确无相关资料；检查空召回与合理克制，补 CRM-025 每题都有相关页的覆盖缺口 |

同客户、同资料家族和同题改写不拆成独立样本；12 根是 6 个家族的成对检查，不称 12 个独立业务分布样本。变更数据的题必须使用等值隔离范围或可验证的状态恢复，禁止上一题污染下一题。资料池共同授权、包含合理干扰项，不能每题只开放答案页。答案与评分不发给作答模型。

本轮是固定当前版本的新任务验证，不再跑旧版本、三专家或版本×记忆×变体的完整组合，不据此宣传修复前后因果收益。看过这些新题结果再改实现后，它们应转为回归材料。

## C / D. 一轮真实运行与判分

先完成记忆三组，再完成泛化；共享队列保持可对账的串行运行，独立离线审查和汇总可并行。每个新请求先落意图，保存 Run、Job、实际模型/配置、工具输入与回执、当前事实/版本、最终回答、用量与时间。保留失败、partial、缺证和参数拒绝，普通质量失败结算该题后继续。

必要字段与引用优先按实际工具事实复核，建议和附加断言由独立评审按冻结规则判定。固定规则优先复用；评审包必须完整保留可核验字段，同时隐藏记忆组、样例标签、用量和待测版本。首次离线正反例检查覆盖：缺项应失败、真正缺证可合理回答、证据未投影不能冒判无据、旧值/串客户失败，以及三种记忆状态均能进入评审证据。

必须分开报告：

- 写入/撤回事实是否生效；必要事实进入上下文数量/应取得数量；字段值与引用正确数量/总数；任务完成数量/总数。
- 旧值、已撤回值、跨客户/跨组织返回及无关记忆误用次数；正确留空与没有完成任务分别统计。
- 泛化各家族的两题关系是否成立、引用语义支持、无答案误答；相关资料命中不能代替最终回答正确。
- 检索、工具调用和端到端耗时；输入/输出/cache、同步/清理与正式读取各自的请求数；金额没有账单就记未知。模型说“已更新”不能替代 SQL 回执。

## 调用上限、自动接续与停止

- A 与 B 不新增产品 Agent / Judge 生成请求；B 中真实 Mem0 同步和查询可能调用 embedding，其请求、用量及耗时单列，不能称全部模型开销为零。正式最多 **30 个根 Run = 18 个记忆检查 + 12 个泛化检查**，专家子任务 0，新增 Judge API 调用 0，默认额外复跑 0。一个根可能有多次模型调用，须照实记录。批次生成模型已报告输入＋输出上限 **1,200,000 token**，cache 单列；每根沿用 12 步/36,000 token 规则。独立评审 Agent 不作为产品模型调用计量，身份如实记录。
- 冻结后正式题各条件只跑一次。第一次调用就是正式槽，不额外开模型校准轮；无需 Agent 生成的预检和历史原件用于验证采集/评分。采集故障补读原 Run，不能新建“替代成功”；基础设施失败照占原槽，记录缺失配对。单根封顶只结算该根，其他安全题继续。
- 按 A→B→C→D→E 连续实施，每批必要验证、独立审查、提交推送后自动下一批，不再等用户重复规划确认。保持本批环境至最终收尾，不在一般失败或阶段完成时拆除。
- 可恢复的采集/环境/评分错误在原范围内处理并对账；评分修改统一作用各组、保存旧分。若必须修改产品才能继续安全调用，先记录未运行槽和受影响范围，限定修复、审查后可以继续未使用槽，但版本不同的结果分开，不追加旧题重跑。
- 记忆效果不好、收益不明显或开销增加均可结束并保留结果，继续泛化部分；不自动调参、扩样本、换模型、扩功能或重构记忆。真正未知业务效果、实际越权、必要账号/权限缺失且无法恢复、或达到调用上限，才暂停依赖步骤并完成其余可做工作。
